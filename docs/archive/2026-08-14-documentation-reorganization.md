## 背景

仓库已经形成模型合同、迁移知识、执行计划和历史归档四个主要分区，但根 README、路线图和测试指南仍混合用户与维护者信息；部分历史分析留在当前迁移知识区；通用文档检查还与一次性模型集成计划耦合。此次整理在不丢失验证证据的前提下收敛入口、状态和自动门禁。

## 范围

- 包含：根 README、ROADMAP、`docs/` 导航与分区、测试指南、计划模板、历史比较归档、文档检查脚本及 CI 门禁。
- 不包含：改写历史报告的日期、环境、数值或结论；修改模型实现、配置、权重、Paddle 参考子模块；引入文档站点生成器。

## 依赖

- 仓库现有 Markdown 和 GitHub 原生渲染继续作为发布载体。
- 使用 uv 管理的 `.venv` 运行文档检查和测试。
- D-FINE、DEIM 与 RT-DETRv4 集成计划是否正式接受由维护者单独决定；本计划不代替该业务验收。

## 目标与非目标

### 目标

- 让新用户、模型使用者、迁移开发者和维护者分别有明确入口。
- 让当前状态、未完成工作和历史证据各自只有一个权威位置。
- 将文档检查改为与具体执行计划无关的通用门禁，并接入 CI。
- 保留全部历史证据及其快照边界。

### 非目标

- 不搭建 MkDocs、Sphinx 或独立文档站点。
- 不为减少行数而删除仍有复现价值的命令和证据。
- 不把技术验收完成自动解释为维护者接受或模型权重发布。

## 风险与回退

- 风险：搬移内容导致相对链接失效。缓解：先保留事实来源，再运行覆盖活动文档和归档的链接检查。
- 风险：历史结论被改写成当前合同。缓解：历史文件只移动并保留快照声明，当前摘要单独重写。
- 风险：通用门禁继续夹带一次性验收规则。缓解：计划专属证据继续由 `tools/dev/audit_plan_evidence.py` 负责。
- 回退：变更按入口、内容迁移和门禁三个独立批次组织，可逐批恢复，不修改代码或模型资产。
